# Task Planning & Decomposition

Use this for multi-step or non-trivial tasks, or when the user asks for a plan.

## Procedure

1. State the goal in one sentence and the definition of "done".
2. Break the work into 3-9 ordered, atomic steps. Each step should be independently verifiable.
3. Mark dependencies and which steps can run in parallel.
4. Identify the riskiest step and address it first.

## Rules

- Prefer fewer, verifiable steps over many vague ones.
- Estimate effort loosely (trivial / small / medium / large) per step.
- If a step is ambiguous, flag the decision needed rather than guessing.

## Output

- A numbered plan with effort and dependencies.
- The recommended first action.
- Use the `todo` tool to track the plan when executing.
